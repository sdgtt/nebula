Cloudsmith Integration in Nebula Downloader
==================================================================
Documentation of the Cloudsmith package source support in nebula downloader.

Overview:
=========
The Cloudsmith integration allows nebula to fetch boot partition files, RPi files,
and firmware from Cloudsmith repositories using the Cloudsmith REST API (v1). It
replaces or supplements the existing Artifactory-based workflow when
--source=cloudsmith is specified.

The implementation is split into two layers:
  1. CloudsmithDownloader class (nebula/cloudsmith.py) - standalone module handling
     all Cloudsmith API interactions, downloads, and verification.
  2. downloader class (nebula/downloader.py) - delegates to CloudsmithDownloader via
     a lazy-loaded property when source == "cloudsmith".

Authentication:
===============
- Requires a service account slug name and API token.
- Passed via CLI argument: --cloudsmith-auth=<user_slug_name>:<cloudsmith_token>
- The downloader class parses this into username and token, then passes them
  to CloudsmithDownloader on first use.
- Used for both API metadata queries (Bearer token) and file downloads (basic auth).

==================================================================
CloudsmithDownloader Class (nebula/cloudsmith.py)
==================================================================

Class Constants:
----------------
  BOOT_PARTITION_REPO = "sdg-boot-partition"
  LINUX_RPI_REPO = "sdg-linux-rpi"
  API_BASE = "https://api.cloudsmith.io/v1/packages/adi"

Constructor:
------------
  CloudsmithDownloader(username, token)
    - Raises an exception if credentials are missing.
    - Initializes a lazy HTTP session with retry logic.

Public Methods:
---------------

  download_boot_files(branch, kernel, dt, board_name, kernel_root,
                      reference_boot_folder=None, boot_subfolder=None,
                      devicetree_subfolder=None, version=None)
    - Entry point for downloading standard boot partition files from Cloudsmith.
    - Resolves the latest version prefix (or uses a provided version path).
    - Constructs a combined API query for all boot file types at once.
    - Downloads and verifies: kernel (Image/uImage), BOOT.BIN,
      bootgen_sysfiles.tgz, and the device tree (.dtb).
    - Files are saved to the "outs/" directory.

  download_rpi_files(branch, arch, version=None)
    - Downloads Raspberry Pi boot and kernel module tarballs from Cloudsmith.
    - Resolves the latest version prefix from the LINUX_RPI_REPO.
    - Downloads: rpi_latest_boot_<arch>.tar.gz and rpi_modules_<arch>.tar.gz.
    - Uses date format "%Y_%m_%d-%H_%M" for RPi version resolution.

  download_firmware(device, version=None)
    - Downloads firmware ZIP files for supported devices (PlutoSDR, ADALM2000).
    - Uses dl.cloudsmith.io direct download URLs with basic auth.
    - Supports versioned downloads or "latest".

Internal Methods:
-----------------

  _get_headers()
    - Returns Authorization (Bearer) and Accept headers for API calls.

  _get_session()
    - Returns a requests.Session with retry logic (3 retries, backoff=0.3,
      retries on 429/500/502/504). Session is reused across all requests.

  _download_file(url, fname)
    - Streams file download with tqdm progress bar.
    - Computes SHA256 hash during download.
    - Appends filename and hash to hashes.txt in the output directory.
    - Uses basic auth (username:token) for download authentication.

  _verify_hash(fname, expected, hash_type="sha256")
    - Reads the file back and verifies against expected hash.
    - Supports md5 and sha256.
    - Raises an exception on mismatch.

  _download_and_verify(package, filename)
    - Combines download and hash verification for a single package.
    - Creates "outs/" directory if needed.

  _paginated_query(query, repo, label="packages", max_pages=3)
    - Generic paginated fetch of packages from Cloudsmith API.
    - Handles both dict-with-"results" and plain-list response formats.
    - Page size: 500. Continues fetching until fewer than page_size results
      are returned or max_pages is reached.
    - Logs warnings when max page limit is hit.

  _filter_completed(packages)  [static]
    - Filters to packages with status "Completed" and format "raw".
    - Extracts only: name, cdn_url, version, checksum_sha256.

  _get_latest_version_prefix(package_version, repo, date_format, kernel_root=None)
    - Fetches all packages matching the version prefix.
    - Parses version strings to extract date segments.
    - Automatically selects the latest build date.
    - Returns the full version prefix path for the latest build.
    - Supports kernel_root matching for common kernel files.

  _build_date_pattern(date_format)  [static]
    - Converts a strftime date format into a regex pattern for matching
      date segments in version strings.

  _match_boot_file(packages, filename, expected_version_path=None)  [static]
    - Finds the correct package from combined results for a given filename.
    - Handles matching for BOOT.BIN, bootgen_sysfiles.tgz, *.dtb, Image/uImage.
    - Uses trailing-slash version path matching to disambiguate sibling DTB
      folders (e.g. adrv9002/ vs adrv9002-rx2tx2/).

==================================================================
Integration in downloader class (nebula/downloader.py)
==================================================================

The main downloader class accesses CloudsmithDownloader through a lazy property:

  @property
  def cloudsmith(self):
      # Creates CloudsmithDownloader on first access
      return CloudsmithDownloader(self.username, self.cloudsmith_token)

Delegation methods in downloader:
  _get_cloudsmith_file(...)       -> self.cloudsmith.download_boot_files(...)
  _get_cloudsmith_rpi_files(...)  -> self.cloudsmith.download_rpi_files(...)
  _download_firmware(... source="cloudsmith") -> self.cloudsmith.download_firmware(...)

These are called from the existing routing logic when source == "cloudsmith":
  _get_files_boot_partition() -> _get_cloudsmith_file()
  _get_files_rpi()            -> _get_cloudsmith_rpi_files()
  _download_firmware()        -> self.cloudsmith.download_firmware()

==================================================================
Invoke CLI Commands (nebula/tasks.py)
==================================================================

dl.bootfiles (download_boot_files)
----------------------------------
Download boot files for a specific development system.

Parameters:
  --source          Boot file download source. Options: local_fs, artifactory,
                    remote, cloudsmith. Default: local_fs
  --source-root     Location of source (domain name for artifactory).
  --branch          Branch name. Default: release
  --board-name      Board config name (e.g. zynq-zc706-adv7511-fmcdaq2)
  --filetype        Type of files to download. Options: boot_partition, hdl_linux,
                    noos, microblaze, rpi, firmware. Default: boot_partition
  --yamlfilename    Path to nebula YAML config. Default: /etc/default/nebula
  --url-template    Custom URL template (Artifactory only).
  --cloudsmith-auth Cloudsmith authentication in format: username:token
  --version         Version path for Cloudsmith downloads. When omitted, the latest
                    available build is fetched automatically. For boot_partition:
                    full version path prefix, e.g.
                    'test_boot_files/main/Linux_PRs/pr_3089/2026_01_22-21_26_59'.
                    For firmware: date string or 'latest'.

CLI Examples:
=============

# Download boot partition files (latest date):
nebula show-log dl.bootfiles --board-name=<board-name> --source=cloudsmith \
    --branch=<branch> --filetype=boot_partition \
    --cloudsmith-auth=<user_slug_name>:<cloudsmith_token>

# Download boot partition files (specific version path):
nebula show-log dl.bootfiles --board-name=<board-name> --source=cloudsmith \
    --branch=<branch> --filetype=boot_partition \
    --cloudsmith-auth=<user_slug_name>:<cloudsmith_token> \
    --version=test_boot_files/main/Linux_PRs/pr_3089/2026_01_22-21_26_59

# Download RPi files:
nebula show-log dl.bootfiles --board-name=<board-name> --source=cloudsmith \
    --branch=<branch> --filetype=rpi \
    --cloudsmith-auth=<user_slug_name>:<cloudsmith_token>

# Download firmware (latest):
nebula show-log dl.bootfiles --board-name=pluto --source=cloudsmith \
    --filetype=firmware \
    --cloudsmith-auth=<user_slug_name>:<cloudsmith_token>

# Download firmware (specific version):
nebula show-log dl.bootfiles --board-name=pluto --source=cloudsmith \
    --filetype=firmware --version=0.39 \
    --cloudsmith-auth=<user_slug_name>:<cloudsmith_token>

# Download SD card image:
nebula show-log dl.sdcard --board-name=<board-name> --source=cloudsmith \
    --branch=<branch> --cloudsmith-auth=<user_slug_name>:<cloudsmith_token>

Architecture Summary
==================================================================

  tasks.py (invoke CLI)
      |
      v
  downloader class (nebula/downloader.py)
      |-- source == "cloudsmith" --> self.cloudsmith property
      |                                  |
      v                                  v
  CloudsmithDownloader (nebula/cloudsmith.py)
      |-- download_boot_files()   [boot partition files]
      |-- download_rpi_files()    [RPi boot + modules tarballs]
      |-- download_firmware()     [firmware ZIPs via dl.cloudsmith.io]
      |
      |-- Internal: _paginated_query(), _get_latest_version_prefix(),
      |             _filter_completed(), _match_boot_file(),
      |             _download_file(), _verify_hash(), _download_and_verify()

==================================================================
Cloudsmith API Details
==================================================================

Repositories used:
  - adi/sdg-boot-partition   (boot files, device trees, kernels)
  - adi/sdg-linux-rpi        (RPi boot + kernel modules)
  - adi/plutosdr-fw          (PlutoSDR firmware, via dl.cloudsmith.io)
  - adi/m2k-fw               (ADALM2000 firmware, via dl.cloudsmith.io)

API endpoint pattern:
  https://api.cloudsmith.io/v1/packages/adi/<repo>/?query=<query>&page=N&page_size=500

Query syntax:
  - version:<prefix>*           Filter by version path prefix
  - name:<pattern>              Filter by filename (supports ^ $ * anchors)
  - Multiple filters: AND / OR  Combined with URL-encoded spaces (%20)

Response formats:
  - JSON list (plain array of package objects)
  - JSON dict with "results" key and "next" URL for pagination

Package fields used:
  - name, cdn_url, version, checksum_sha256, status_str, format

Version string structure:
  boot_partition/<branch>/<date>/<path>/<board>
  e.g. boot_partition/2026_r1/2026_01_15-08_30_00/boot_partition/adi-zynqmp/board-name

Date formats:
  - Boot partition: %Y_%m_%d-%H_%M_%S (e.g. 2026_01_15-08_30_00)
  - RPi: %Y_%m_%d-%H_%M (e.g. 2026_01_15-08_30)

Known Considerations:
=====================
- Cloudsmith REST API v1 may return a plain JSON list or a paginated dict.
  The implementation handles both formats transparently.
- The API token is passed as Bearer token for metadata queries, but basic auth
  (username:token) is used for file downloads via dl.cloudsmith.io/cdn.
- Session reuse: a single requests.Session is shared across all API and download
  calls for connection pooling and retry efficiency.
- Max pages default is 3 (up to 1500 packages per query). A warning is logged
  if this limit is reached.
- The _match_boot_file method uses trailing-slash matching on version paths to
  correctly disambiguate boards with similar name prefixes.
